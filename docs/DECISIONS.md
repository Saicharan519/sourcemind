# Decision log

Newest at the bottom. Each entry: what was decided, and why.

## 2026-11-12: Improve the existing repo, don't rewrite it
The architecture (async ingestion, hybrid retrieval, parent/child chunking, SSE streaming) is sound. What was missing was rigor: evaluation, tests, security, honest claims. A rewrite would throw away working code and gain nothing.

## 2026-11-12: Measure first, then change
A benchmark is built (Phase 1) before any retrieval change, so every later change is judged against numbers instead of intuition. Every component must earn its place; anything that doesn't help is removed and recorded as a negative result.

## 2026-11-12: Pin LLMs to Groq production models
- Main: `openai/gpt-oss-120b`. Fast: `openai/gpt-oss-20b`.
- `qwen/qwen3.8-27b` was rejected because it is a Groq *preview* model and can be withdrawn at short notice. A model change partway through invalidates every ablation.
- Every eval result file records the model IDs it ran with.

## 2026-11-12: Tag `v1-as-shipped`
The pre-2.0 code is tagged so it can always be re-measured as ablation arm 1. The tag must never move.

## 2026-11-12: The benchmark is AI-generated and human-reviewed, not hand-written
- Questions are generated by the fast Groq model from random pages across each document.
- A model from a different family (Mistral) cross-checks each one: is the answer on the cited page, is the question unambiguous, is an "unanswerable" question really unanswerable?
- A human reviews every flagged question, every unanswerable and multi-hop test question, and a random sample of the rest.
- Why: hand-writing 140+ questions would take days. Two models from different families plus targeted human review is a defensible middle ground, and it is described honestly in the README.

## 2026-11-12: Gold labels are pages and time windows, never chunk IDs
Chunking is one of the things being tested. Chunk IDs change whenever chunking changes; page numbers and video timestamps don't. So the same benchmark stays valid across every experiment.

## 2026-11-12: Pilot before scaling
The whole pipeline (generate → cross-check → review → run → score → report) is first run on about 40 questions. Harness bugs are cheap to find at that size and expensive at 440.

## 2026-11-12: Benchmark runs in an isolated database and collection
The eval uses its own Postgres database (`sourcemind_eval`) and Qdrant collection (`sourcemind_eval`), so benchmark runs never touch the sources you use in the app.

## 2026-11-12: Corpus PDFs are downloaded, not committed
`*.pdf` is gitignored. The corpus is defined by `eval/corpus/manifest.yaml` (URL, license, SHA-256), and `download.py` fetches and verifies each file. A changed file fails the hash check, so the benchmark can't silently drift.

## 2026-11-12: Corpus selection
- Papers: only arXiv papers whose metadata shows a CC license (RAGAS, Self-RAG: CC BY 4.0; BEIR: CC BY-SA 4.0). Seven other RAG papers checked were under arXiv's default non-exclusive license and were excluded.
- Standards and reports: NIST (AI RMF, GenAI Profile, CSF 2.0, SP 800-63B), Census P60-282 and the Fed Financial Stability Report, all US federal publications. GAO and CBO were dropped because their servers block scripted downloads (timeout / 403).
- Lectures: three MIT OpenCourseWare Lecture 1s (CC BY-NC-SA 4.0).
- The RAG papers overlap in topic on purpose: near-duplicate subject matter makes retrieval harder and more realistic.

## 2026-11-12: Benchmark answers accept every page that holds an exact answer
For short factoid / exact-ID answers, if the same answer string appears on up to 3 other pages of the document (e.g. a publication date on both the cover and the colophon), those pages are added to the gold evidence. Found in the first dry run: the system correctly cited the cover page and was wrongly scored as a miss.

## 2026-11-12: Pilot cross-check used a same-family model
No `MISTRAL_API_KEY` was configured yet, so the ~40-question **pilot** was cross-checked with `gpt-oss-120b` (same family as the `gpt-oss-20b` generator), and every record says so. The full benchmark will be cross-checked and judged by Mistral. No pilot number is a resume number.

## 2026-11-12: DeepSeek replaces Mistral as the independent checker and judge
Mistral's console now requires a paid plan before API keys work. DeepSeek (`deepseek-flash`, OpenAI-compatible API) is a different model family from the `gpt-oss` models that generate the questions and the answers, which is what the cross-check and judge need. It costs about $0.15 per 1M input tokens, so checking and judging the whole benchmark is under $1. Configured via `DEEPSEEK_API_KEY` in `backend/.env`; Mistral remains a fallback.

## 2026-11-12: Rate-limited helper steps must never be scored as normal answers
Found in the first pilot run: when Groq rate-limits HyDE, multi-query or the classifier, the backend logs "failed" and **silently answers with a weaker pipeline**. The harness now captures those log lines per question; a rate-limited helper is retried, and any answer that still ran degraded is marked `degraded` and re-asked on resume. (Fixing the silent fallback in the app itself is a Phase 2 item.)

## 2026-11-12: Groq's free tier caps each model at 200K tokens/day
Question generation, cross-checking and one pilot run used up both models' daily quota on the first day. A full benchmark run (about 440 questions × several arms) cannot fit in the free tier at that rate, so how to fund the system-under-test calls is an open decision (see PROGRESS.md).

## 2026-11-12: Simple auth, ₹0 budget, no paid hosting
Multi-user isolation (Phase 5) uses password + JWT, not emailed OTP: the project runs locally, so email infrastructure adds work without adding interview value. Deployment is Docker Compose + a static project page with a replay demo.
